# YM7129 (OPK) 波形分析报告

基于硬件逻辑分析仪抓包数据整理。

## 1. 总线时序

来源: `时序说明.txt`

| 参数 | 值 |
|------|-----|
| CS 下降脉冲宽度 | 320ns |
| IC 下降沿复位时间 | 184ms |
| IC 高电平后到第一个 CS 下降沿 | 105us |
| A0 低 = 地址, 高 = 数据 (先低后高) | - |
| 地址 CS 下降沿到数据 CS 下降沿 | 8.6us |
| 连续 2 次写入间隔 | 89.2us |

**关键**: YM7129 使用 **A0 分离的地址/数据总线**，不是复用总线。每个寄存器写入需要两次操作：
1. A0=低，CS下降沿 → 写入地址
2. A0=高，CS下降沿 → 写入数据

两次写入之间间隔 8.6us，连续两次完整写入间隔 89.2us。

## 2. SPFM Light 通信协议

### 两种写入方式

**方式 1: 4 字节 port-based 协议（原始方式）**

```
[slot, port<<1, addr, data]
```

`spfm_write_reg(slot, port, addr, data)` — 将地址和数据合并为一个 USB 包。
SPFM Light 固件内部处理 A0 时序。已通过 SAA1099 实测验证可用。

**方式 2: 3 字节 raw 协议（推荐，满足 YM7129 时序）**

```
[slot, 0x80, addr]   → 写地址 (A0=0)
[slot, 0x81, data]   → 写数据 (A0=1)
```

`spfm_write_raw(cmd, 6)` — 地址和数据分开发送，两次写入间隔 5-10us，
**完全满足 YM7129 的 8.6us A0 间隔要求**。

> 注意: SAA1099 驱动中 Protocol 1 使用的是相反的 0x81=地址/0x80=数据，
> 这是因为 SAA1099 与 YM7129 的 A0 极性不同。YM7129 应使用 0x80=地址、0x81=数据。

### YM7129 驱动应使用方式 2

```c
void ym7129_write(uint8_t addr, uint8_t data) {
    uint8_t cmd[6];
    cmd[0] = slot; cmd[1] = 0x80; cmd[2] = addr;  // A0=0, latch address
    cmd[3] = slot; cmd[4] = 0x81; cmd[5] = data;  // A0=1, write data
    spfm_write_raw(cmd, 6);
}
```

## 3. $80-$84 鼓寄存器（硬件波形验证）

来源: `数据分析.xlsx` sheet2 + sheet4 + `节奏/` 目录下 7 个逻辑分析仪抓波文件

### $80-$83 格式（硬件实测确认）

```
bit7     L/H      高低2种大类型 (Low=1, Hi=0)
bit6-4   Rhy.No   0-6, 7种小类型
bit3-0   Rhy.Vol  0-15, 0=最大, 15=最小
```

| Rhy.No | 乐器 |
|---------|------|
| 0 | BD (Bass Drum) |
| 1 | SD (Snare Drum) |
| 2 | C.HH (Closed Hi-Hat) |
| 3 | O.HH (Open Hi-Hat) |
| 4 | Tom |
| 5 | Ride |
| 6/7 | **Play all** — 同时播放全部采样（用户实测确认） |

> madscient 原表把 6/7 标为 "Reverse all"，实为 **Play all**：一次触发所有采样同时发声。

### $84 触发寄存器格式

| bit3 | bit2 | bit1 | bit0 |
|------|------|------|------|
| k3 (通道4/$83) | k2 (通道3/$82) | k1 (通道2/$81) | k0 (通道1/$80) |

### 触发方式（硬件验证 - 7个文件交叉确认）

**$84 是上升沿触发: 对目标通道的 bit 先写 0 → 再写 1 = 敲击一次。**

这不是简单的 active-high 或 active-low，而是 **0→1 的电平跳变** 触发。

#### 验证证据

**文件 0.txt** — 完整的 0→1 递增触发序列（最清晰的演示）:
```
Strike 1: $80=$83  CH1=BD(L) Vol=3
  $84=$00 (all off)
  $84=$01 (bit0: 0→1, CH1 触发!)

Strike 2: $81=$55  CH2=Ride(H) Vol=5
  $84=$01 (保持)
  $84=$03 (bit1: 0→1, CH2 触发!)

Strike 3: $80=$83  CH1=BD(L) Vol=3
  $84=$02 (bit0: 1→0, 关闭CH1)
  $84=$03 (bit0: 0→1, CH1 再次触发!)

Strike 4: $82=$C4  CH3=Tom(L) Vol=4
  $84=$03 (保持)
  $84=$07 (bit2: 0→1, CH3 触发!)
```

**文件 1.txt** — 稳态运行模式（所有通道已在上一轮激活后保持为 1）:
```
Strike: $82=$84  CH3=BD(L) Vol=4
  $84=$0B (bit2: 1→0, 关闭CH3)
  $84=$0F (bit2: 0→1, CH3 触发!)

Strike: $80=$2A  CH1=C.HH(H) Vol=10
  $84=$0E (bit0: 1→0, 关闭CH1)
  $84=$0F (bit0: 0→1, CH1 触发!)
```

**文件 14.txt** — 使用 $00=$FE 初始化（未写 $01）:
```
$00=$FE  (TEST 寄存器)
$82=$86  CH3=BD(L) Vol=6
$84=$0A  (bit2: 0→1, CH3 触发!)
$84=$0E  (bit1: 0→1, CH2 触发!)
```

**文件 13.txt** — 使用 3 通道的逐步展开模式:
```
Strike 1: $80=$82  CH1=BD(L) Vol=2
  $84=$00, $84=$01 (bit0 上升沿)

Strike 2: $81=$28  CH2=C.HH(H) Vol=8
  $84=$01, $84=$03 (bit1 上升沿)

Strike 3: $82=$12  CH3=SD(H) Vol=2
  $84=$02, $84=$03 (bit1 先关再开 = CH2 再次触发!)
```

| 参数 | 值 |
|------|-----|
| 鼓类型设置 ($80-$83) 到触发 ($84=0) | ~1.7ms |
| $84=0 到 $84=1 的间隔 | ~1.7ms |
| 两次完整触发的总线周期 | ~3.5ms |
| addr-data 总线间隔 | ~216us |

## 4. FM 寄存器详解（经验证版本）

来源: `数据分析.xlsx` sheet4 (经验证的完整寄存器表) + sharedStrings 中文注释

### 完整寄存器地址映射

| 地址范围 | 类型 | 说明 |
|----------|------|------|
| $00 | TEST-E | 测试/使能寄存器 (硬件验证新发现) |
| $01 | RHY-PAN | 鼓左右声道选择: bit0-3=Rhy0-3 L, bit4-7=Rhy0-3 R（$FF=全开） |
| $02-$0F | - | 无效 |
| $10-$1F | MLWS | 调制器/载波 Kon/VIB/AM/WS/DM/EG-TYP/ML |
| $20-$2F | TL | 调制器/载波音量 |
| $30-$3F | ARDR | Attack/Decay Rate |
| $40-$4F | SLRR | Sustain Level / Release Rate |
| $50-$5F | FNUM-H | BLK + F-NUM MSB (奇数地址=Mirror) |
| $60-$6F | FNUM-L | F-NUM LSB (奇数地址=Mirror) |
| $70-$77 | L/R/FB | 声道选择 + 反馈 |
| $78-$7F | - | 未使用 |
| $80-$83 | RHY | 鼓通道设置 (类型/音量) |
| $84 | RHY-TRG | 鼓触发寄存器 |

### 通道与操作器映射

每个 FM 通道由 1 个调制器 (M) + 1 个载波 (C) 组成，8 个通道共 16 个操作器:

| CH | 调制器寄存器 | 载波寄存器 |
|----|-------------|-----------|
| 0 | $10/$30/$40/$50/$60 | $12/$32/$42/$52/$62 |
| 1 | $11/$31/$41/$51/$61 | $13/$33/$43/$53/$63 |
| 2 | $14/$34/$44/$54/$64 | $16/$36/$46/$56/$66 |
| 3 | $15/$35/$45/$55/$65 | $17/$37/$47/$57/$67 |
| 4 | $18/$38/$48/$58/$68 | $1A/$3A/$4A/$5A/$6A |
| 5 | $19/$39/$49/$59/$69 | $1B/$3B/$4B/$5B/$6B |
| 6 | $1C/$3C/$4C/$5C/$6C | $1E/$3E/$4E/$5E/$6E |
| 7 | $1D/$3D/$4D/$5D/$6D | $1F/$3F/$4F/$5F/$6F |

**Mirror 寄存器**: $50=mirror of $52, $51=mirror of $53 等（奇数 FNUM-H 地址是偶数的镜像，同样适用于 FNUM-L）

### $00 TEST-E 寄存器（硬件验证新发现）

| bit7 | bit6 | bit5 | bit4 | bit3 | bit2 | bit1 | bit0 |
|------|------|------|------|------|------|------|------|
| - | - | - | - | - | D | C | B | A |

**实测含义 (经验证):**
- bit3 (A): A=1 奇怪的调制波形
- bit2 (B): B=1 复位
- bit1 (C): C=1 Kon 失效无法关闭
- bit0 (D): D=1 过度调制波形

### $01 鼓左右声道选择 (RHY-PAN)

**来源**: `数据分析.xlsx` Sheet1 第 3 行（2026-06-23 更新）

| bit7 | bit6 | bit5 | bit4 | bit3 | bit2 | bit1 | bit0 |
|------|------|------|------|------|------|------|------|
| Rhy3_R | Rhy2_R | Rhy1_R | Rhy0_R | Rhy3_L | Rhy2_L | Rhy1_L | Rhy0_L |

- bit0-3: 节奏通道 0-3 的左声道输出使能
- bit4-7: 节奏通道 0-3 的右声道输出使能
- 初始化写 `$FF` = 四路鼓全部 L+R。早期文档把它当成"必须写 0xFF 的 TEST 寄存器"，
  实为四路鼓声道全开。

### $10-$1F: MLWS (Kon/VIB/AM/WS/DM/EG-TYP/ML)

**调制器 (Modulator, 奇数地址 $10+$offset):**

| bit7 | bit6 | bit5 | bit4 | bit3 | bit2 | bit1 | bit0 |
|------|------|------|------|------|------|------|------|
| - | VIB | DM | EG-TYP M | ML(M) |

- bit7: 调制器无 Kon 位 (空/无效)
- bit6 (VIB): 颤音开关，作用于频率
- bit5 (DM): 波形类型。0=标准正弦波，1=半正弦整流波
- bit4 (EG-TYP M): 调制器包络类型（madscient 标注，经验证版保留）
- bit3-0 (ML): 倍频

**载波 (Carrier, 偶数地址 $12+$offset):**

| bit7 | bit6 | bit5 | bit4 | bit3 | bit2 | bit1 | bit0 |
|------|------|------|------|------|------|------|------|
| Kon | AM | WS | EG-TYP | ML(C) |

- bit7 (Kon): Key-on，设为 0x80 激活
- bit6 (AM): 颤音开关，作用于振幅
- bit5 (WS): 波形类型。0=标准正弦波，1=半正弦整流波
- bit4 (EG-TYP): 包络形状。0=常规释音持续型，1=强制衰减型
- bit3-0 (ML): 倍频。0=降低一半频率，1=正常，2=2倍，3=3倍...

**经验证版修正**: 载波 B6=AM (非VIB), 调制器 B4=EG-TYP M (原版为空)

### $20-$2F: TL (音量)

**调制器 (偶数地址 $20+$offset):**

| bit7-0 |
|--------|
| TL(M)  |

- 8bit 整体值 = 调制音量, 0=最大, 255=最小

**载波 (奇数地址 $22+$offset):**

| bit7 | bit6-0 |
|------|-------|
| DP | Volume |

- bit7 (DP): Force damping (1=强制衰减)
- bit6-0 (Volume): 0=最大音量, 127=最小音量

### $30-$3F: ARDR (Attack/Decay Rate)

| bit7-4 | bit3-0 |
|--------|--------|
| AR | DR |

- AR (Attack Rate): 起音速率
- DR (Decay Rate): 衰减速率

### $40-$4F: SLRR (Sustain Level / Release Rate)

| bit7-4 | bit3-0 |
|--------|--------|
| SL | SR/RR |

- SL (Sustain Level): 0=最高电平, 15=最低 (与其他芯片相反!)
- SR/RR: Kon=1 时为 Sustain Rate, Kon=0 时为 Release Rate

### $50/$52/$56/$5A/$5E: BLK/FNUM MSB

| bit7-5 | bit4-0 |
|--------|--------|
| BLK | FNUM[10:6] |

- BLK (Block): 0-7, BLOCK 最大值 7
- FNUM (MSB): 高 5 位
- BLOCK: B7-B5三位, F-NUM: B4-B0五位

### $60/$62/$66/$6A/$6E: FNUM LSB

| bit7-2 | bit1-0 |
|--------|--------|
| FNUM[5:0] (左对齐) | 未使用 |

- 硬件实测确认低 2 位未使用

### $70-$77: L/R/FB

| bit7 | bit6 | bit5 | bit4 | bit3 | bit2 | bit1 | bit0 |
|------|------|------|------|------|------|------|------|
| ? | R | L | ? | ? | FB | | |

- bit7: PSS-280 样本中使用了，含义未知
- bit6 (R): 右声道
- bit5 (L): 左声道
- bit2-0 (FB): 反馈 (经验证版: FB 在 B2-B0 位)

**注意**: 经验证版本中 FB 位置从 B3-0 修正为 B2-0（具体位置待进一步确认）

## 5. 频率计算

来源: `数据分析.xlsx` sheet4 + `opk_register html/Sheet3.html`

**公式 A (数据分析.xlsx，实测验证):**
```
F-NUM = (音频频率 × 2^25) / (时钟频率 × 2^BLOCK)
```

**公式 B (madscient/Sheet3.html):**
```
F-NUM = (fmus × 2^19) / fsam / (2^BLK)
其中 fsam = 3.579545MHz / 108 = 33.144kHz
```

两种公式本质相同（公式B考虑了内部采样率分频）。

- 时钟频率: 3.579545 MHz
- BLOCK 最大值: 7
- F-NUM 最大值: 511
- 注意: F-NUM 不能超过 511，如果计算值过大可增加 BLOCK

### 示例

| 音名 | 频率(Hz) | 5X(MSB) | 6X(LSB) |
|------|----------|---------|---------|
| C4 | 262 | 0x73 | 0x30 |
| D4 | 294 | 0x75 | 0x80 |

## 7. 与 OPLL 的对比

> YM7129 的 FM 部分与 OPLL 非常相似，但有以下关键差异。

### YM7129 vs OPLL 差异

| 特性 | OPLL (YM2413) | YM7129 (OPK) |
|------|---------------|--------------|
| KSR (Key Scale Rate) | 有 | **无** |
| KSL (Key Scale Level) | 有 | **无** |
| Inst (内置乐器) | 有 ($10-$1F 选乐器号) | **无** (完全可编程) |
| WS (波形选择 bit5) | 无 | **有** (载波WS, 调制器DM) |
| EG-TYP (包络类型 bit4) | 无 | **有** (仅载波) |
| AM (载波振幅调制 bit6) | 无 | **有** |
| 鼓通道 | 有 (3ch, 内置) | **有** (4ch, PCM rompler) |
| 频率寄存器 | 独立 | 有 Mirror 寄存器 |

### 新发现的位含义 (硬件验证)

- **WS (bit5, 载波)**: 波形选择。0=正弦波, 1=半波整流。
- **DM (bit5, 调制器)**: 波形类型。0=正弦波, 1=半波整流。
- **EG-TYP (bit4)**: 包络类型选择。仅对载波有效。0=持续型, 1=衰减型。
- **AM (bit6, 载波)**: 载波振幅调制。实测确认有效。
- **VIB (bit6, 调制器)**: 调制器频率调制。与AM类似，作用于频率。

## 8. PSS-26 dump 中的不一致

PSS-26 dump (`$1A=0x01`) 使用 ML=0x01，而实测初始化使用 ML=0x0D。
这说明不同型号/固件版本可能有不同的初始化参数。

## 9. FM 音色参数（硬件抓波实测）

来源: `YM7129 逻辑\FM\` 目录下的逻辑分析仪抓包文件

每个文件名对应一种音色/效果，从 PSS 系列原机 Z80 总线抓取。数据格式为连续的 `[地址, 数据]` 对。

### 通用初始化序列

所有音色文件共享相同的初始化序列（PSB 固件默认值）:

```
所有通道载波: MLWS = 0x01 (ML=1), SLRR = 0x0B (SL=0, RR=11)
$70-$77 L/R/FB = 各通道独立
```

### 音色表

#### sine (纯正弦波)

最简单的音色——纯载波，无调制。

| 寄存器 | 载波 (ch3) | 调制器 (ch2) |
|--------|-----------|-------------|
| MLWS | 0x11 (EG-TYP=1, ML=1) | 0x00 |
| TL | 0x30 (Vol=48) | 0xFF (静音) |
| ARDR | 0x00 | 0x00 |
| SLRR | 0x05 | 0x00 |
| L/R/FB | 0xE0 (L+R, bit7=1) | - |
| FNUM | BLK=3, FNUM=1228 | - |
| Key-on | $16=0x91 (Kon+EG-TYP) | - |
| Key-off | $16=0x11 | - |

**特点**: 调制器 TL=0xFF(静音)，纯载波输出。Kon=0x91 同时设 Kon+EG-TYP。
**L/R/FB bit7**: sine/DC2 文件中 bit7=1 (0xE0)，其他文件中 bit7=0。可能影响某种全局开关。

#### C (Carrier 音色, ch3)

与 sine 类似但无 EG-TYP，用 SLRR 控制衰减。

| 寄存器 | 载波 (ch3) | 调制器 (ch2) |
|--------|-----------|-------------|
| MLWS | 0x01 (ML=1) | 0x00 |
| TL | 0x39 (Vol=57) | 0x94 (弱调制) |
| ARDR | 0x00 | 0x00 |
| SLRR | 0x06 (RR=6) | 0x00 |
| L/R/FB | 0xE0 (L+R, bit7=1) | - |
| FNUM | BLK=3, FNUM=1228 | - |
| Key-on | $16=0x81 (Kon only) | - |
| Key-off | $16=0x01 | - |

**特点**: 调制器 TL=0x94(弱调制)，载波 SLRR=0x06(衰减后释放)。Kon=0x81 仅设 Kon 位。

#### DC (Down-chirp 下行滑音, ch5→ch3)

双音连续下行的滑音效果，载波 TL=0x39, 调制器 TL=0x94。先触发 ch5 (FNUM=0x7350=1300)，然后触发 ch3 (FNUM=0x7330=1228)。

| 寄存器 | ch5 | ch3 | ch4 | ch2 |
|--------|-----|-----|-----|-----|
| MLWS | 0x01 | 0x01 | 0x01 | 0x01 |
| TL | 0x39 | 0x39 | 0x94 | 0x94 |
| SLRR | 0x0B→0x12→0x14 | 0x0B→0x12→0x14 | 0x0B→0x12→0x14 | 0x0B→0x12→0x14 |
| FNUM | 0x7350 (1300) | 0x7330 (1228) | 0x7330 (1228) | 0x7330 (1228) |
| L/R/FB | 0xE0 | 0xE0 | 0xE0 | 0xE0 |
| Kon触发 | $1A=0x81 → $13=0x81 | $16=0x81 | $1A=0x81 | $16=0x81 |

**滑音机制**: SLRR 先设 0x12 (SL=1, RR=2=短衰减) 再改为 0x14 (RR=4)，形成音量先升后降再释放的效果。

#### DC2 (下行滑音变体, ch3→ch7)

与 DC 类似但使用不同通道组合，且 ch6-ch7 配置了 EG-TYP=True + 特殊 ARDR。

**特点**: ch6 调制器 MLWS=0x13 (EG-TYP=1, ML=3)，与 DC 的普通 0x01 不同。

### 关键发现总结

1. **L/R/FB bit7 是全局使能/特殊模式位**: sine/DC/DC2 文件中 L/R/FB 使用 0xE0 (bit7=1)，而 3/11/21/ufo 使用 0x00-0xE0 之间的值。DS/SD 文件先写 0x60 再写 0xE0。可能 bit7=1 时的行为不同。
2. **EG-TYP=True (bit4=1) 创造快速衰减音色**: DS/SD/ufo 中大量使用 EG-TYP=1，配合 ARDR=0xEF/0xBF (AR=14/11, DR=15) 实现噪声-like 的快速衰减。
3. **FB=5 是和弦音色的标准反馈**: 3/3-C 中所有通道 FB=5。
4. **FNUM-H/LSB 写入可以实时改变音高**: 11/21 文件中通过反复写入不同 FNUM 值实现滑音。
5. **Kon 触发方式**: 对载波寄存器写 Kon 位 (0x80)，然后清除 Kon 位实现音符结束。

### $84 触发模式总结

#### 模式 A: 逐步展开 (0→F) — 文件 0.txt, 13.txt, 节奏.txt

每个 beat 从 $84=0 开始，逐步将各通道 bit 设为 1，每次只触发一个通道:

```
Beat 1: $80=BD    → $84=00 → $84=01 (CH1 触发)
        $81=Ride  → $84=01 → $84=03 (CH2 触发)
        $80=BD    → $84=02 → $84=03 (CH1 再次触发, 注意先 0 再 1)
        $82=Tom   → $84=03 → $84=07 (CH3 触发)
        $81=Ride  → $84=05 → $84=07 (CH2 再次触发)
        $83=SD    → $84=07 → $84=0F (CH4 触发)
        → 所有 4 通道已激活 ($0F)，下一个 beat 开始...

Beat 2: $80=C.HH  → $84=0E → $84=0F (CH1 触发)
        $81=Ride  → $84=0D → $84=0F (CH2 触发)
        ...
```

**关键**: 每个 beat 内的多次打击并不是独立的，而是共享同一个 $84 累加值。
第一个 beat 从 $00 开始逐位累加到 $0F，后续 beat 维持 $0F 状态，
每次只需将目标位先清 0 再置 1 即可触发。

#### 模式 B: 稳态运行 — 文件 1.txt, 2.txt, 12.txt

所有通道已激活 ($84 维持 $0F)，每次打击只操作目标通道的 bit:

```
Strike CH3(BD):   $84=0B → $84=0F  (bit2: 1→0→1)
Strike CH1(C.HH): $84=0E → $84=0F  (bit0: 1→0→1)
Strike CH2(O.HH): $84=0D → $84=0F  (bit1: 1→0→1)
Strike CH3(SD):   $84=07 → $84=0F  (bit2: 1→0→1, CH3 重新配置为 SD)
```

#### 模式 C: 双通道触发 — 文件 14.txt

只使用 CH2 ($82) 和 CH3 ($84 bit2)，每次触发 2 个通道:

```
$00=$FE          (特殊 TEST 初始化)
$82=$86  BD(L)   → $84=0A → $84=0E  (bit2 和 bit3 各自 0→1)
$82=$2A  C.HH(H) → $84=06 → $84=0E  (bit1 和 bit2 各自 0→1)
```

$0A = bit3+bit1: 同时触发 CH4 + CH2
$0E = bit3+bit2+bit1: 同时触发 CH4 + CH3 + CH2

**注意**: $84=$0A 触发的是 bit3(CH4) 而不是 bit2(CH3)！
但 $82 的鼓类型配置是给 CH3 用的。说明 bit3 可能不是简单的通道映射。

### $84 bit3 的特殊含义

在 14.txt 中:
- $82=$86 配置的是 CH3（地址 $82 = 通道3）
- 但触发使用 $84=$0A (bit3=1, bit2=0) 和 $84=$0E (bit3=1, bit2=1)
- bit3 是 CH4 的控制位，但 $83 没有被写入

**可能解释**: bit3 在 14.txt 的 $00=$FE 模式下含义不同，
或者 bit3 控制的不是 $83 通道而是其他功能。
需要更多测试验证。

### 触发时序（所有文件一致）

```
设置鼓类型 ($80-$83) → 等待 ~1.7ms → $84=clear → 等待 ~1.7ms → $84=set
总触发周期: ~3.5ms (从设置类型到完成触发)
$84 两次写入间隔: ~1.7ms
总线 addr→data: ~216us (固定)
```

### 鼓声类型分布统计

| 乐器 | L 类型次数 | H 类型次数 | L/H 比例 |
|------|-----------|-----------|---------|
| BD | 15 | 0 | 100% L |
| Tom | 10 | 0 | 100% L |
| SD | 0 | 8 | 0% L |

### 驱动实现要点

```c
// 正确的鼓触发流程:
void ym7129_drum_strike(uint8_t channel, uint8_t rhy_type, uint8_t lh, uint8_t volume) {
    // 1. 设置鼓类型和音量
    uint8_t type_val = (lh << 7) | ((rhy_type & 7) << 4) | (volume & 0x0F);
    ym7129_write(0x80 + channel, type_val);

    // 2. 触发: 先 clear 目标 bit, 再 set 目标 bit
    uint8_t bit_mask = (1 << channel);
    uint8_t cur = drum_trigger_state;
    ym7129_write(0x84, cur & ~bit_mask);  // clear
    ym7129_write(0x84, cur | bit_mask);   // set (rising edge!)
    drum_trigger_state = cur | bit_mask;
}

// 音量: 0=最大, 15=最小 (反直觉!)
// BD/Tom 用 L(lh=1), SD/C.HH/O.HH/Ride 用 H(lh=0)
```
